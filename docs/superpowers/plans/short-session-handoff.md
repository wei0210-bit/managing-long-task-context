## 2. 原则、范围与基线

三项用户原则（T:L22867、T:L22884）：

1. **有效、精致而经济**：有效性不可降低；减少长会话历史负担是核心价值；复用已有机制、减少重复记录和管理调用。
2. 保留定性判断，能合理量化时尽量量化。数字须说明对象、单位或分母、触发动作与例外；硬要求、待校准阈值、实测收益分开。
3. 每个重要讨论点不重不漏。有唯一归属和处理状态；完整覆盖不要求同批开发，后置不等于删除。

产品目标：准确外置项目记忆，使长期任务通过干净短会话持续完成；不靠旧聊天，也不反复全库探索。追求的是同等任务质量下的**系统总成本**下降，不是会话越短越好。

范围：Strict 的可信接续层、主控与执行者分别交接、在途任务连续性、两宿主三路径适配、Lite 轻量恢复，以及成本观测。排除：新建通用调度平台或常驻运行管理器、重写证据解析器、自动把经验晋升为权威规则、替代宿主权限系统、用提示词冒充门禁。

## 4. 唯一需求目录

### R01 核心价值

项目记忆属于项目，会话只是临时工作台。先打通“准确外置 → 最小恢复 → 实际换干净会话”；只做摘要而未减少长会话依赖不能算实现核心收益。保持有效、精致、经济的次序；不以减少主控窗口掩盖子 Agent 消耗和返工。

### R02 项目记忆与分层归属

固定入口优先复用项目现有 STATUS／CONTEXT，没有才新建；不得另维护同义状态。保存／引用决策、约束、当前状态、接口变化、已知问题、标准，并补齐授权、未决动作及重试限制、下一步。总 Agent 保存目标、基线、依赖、活跃执行归属、待验收与阻塞；子 Agent 保存自身合同、接口、工作区、进度、证据与未决动作；共同规则和原始证据按引用共享。每层责任人维护自己的记录，避免相互覆盖。

### R03 事实可信与来源

承重事实关联稳定引用、适用范围、版本、观察时间和验证状态。verified、stale、unknown、conflicted 不得混写；可变事实重新观察。新事实以可追溯失效／替代关系取代旧事实，不能覆盖审计历史。外置详情不等于生成新事实或刷新验证时间；经验先为候选，不能在 flush 时获得规则权威。摘要、合法 JSON、路径存在、hash 或自填 pass 均不能独立证明业务事实。

### R04 精简读取与增量 flush

默认只读固定入口、当前任务 brief/NOW 及必需引用；原证据由既有 resolver/verifier 按需核查；完整事件／日志只用于具体分歧。不能用 grep/head 截到成功文本替代完整判据验证。flush 只记录变化，无变化不重复检查点；失败、冲突或超限时不损坏上一份有效记录，不裁掉承重信息或盲目提高预算。不能把长聊天改成长文档后每次全读。

CEO-D8：版本化交接清单引用本次必需工件，既有事件流中的最终提交记录是完整发布依据，固定入口只是可重建导航。先准备明确版本工件并核验，再在短锁内核对预期代次与关键依据并提交，不在锁内等待模型。清单／hash 不替代证据内容、时效、授权或激活检查；变化文件不能混合代次发布。缺必需项或空必需工件拒绝发布，确认无变化则不产生新代次。写入失败保留旧完整版本供只读恢复，不恢复旧权限；提交后导航失败须检测并恢复投影，不回退已生效控制权。提交未知按 CEO-D6 核对，不能凭报错或入口未更新重发。稳定请求标识、错误码、持久性及故障注入点在工程审核冻结，进程中断与机器掉电分别验证。

### R05 总 Agent 生命周期

U-R01：总 Agent 独立监测自身上下文，达到配置的预警条件时提醒并准备交接；在下一个可安全移交点，宿主能力已验证且原授权覆盖时优先自动创建干净会话，按 R09 核验与激活，不要求重复人工批准。触发量和阈值语义归 R15；宿主不支持自动创建／交接时明确提醒，给出外置资料入口和最短手动步骤，不声称自动切换。提醒、记录准备、创建会话、核验通过和激活完成分别表达；只提醒或只保存文档不算短会话接续功能完成。

里程碑或较大工作单元完成、进入不同阶段、上下文明显膨胀时检查 rollover。还有工作且可安全交接才换；不可安全移交的动作记录暂缓原因和下一检查点；工作结束则关闭，不开空会话。准备阶段按 CEO-D5 暂停旧主控的新派单、resume 指令及改变执行安排的操作；已登记授权子任务继续执行和落盘。旧主控可只读核查，新主控激活前也不能调度。只有新会话核验、控制权移交及在途结果归属清楚后才归档；归档不删历史，重开旧会话不能直接沿旧下一步执行，归档 UI 不证明进程已停止。

### R06 子 Agent 生命周期与任务连续性

U-R01：每个子 Agent 分别监测自己的上下文，不用总 Agent 的占用代替，也不把各子任务累计用量相加当成单会话长度。触发后在当前工作单元的安全检查点按原合同换干净执行实例；没有安全点则保留暂缓原因及下一检查点，不强切。总控换会话不联动重建仍正常工作的子 Agent，子 Agent 换实例也不重建逻辑任务。

同一工作单元按“实施 → 测试 → 提交证据 → 合同要求的独立验收 → 必要返修 → 验收通过 → 外置记录 → 退出”保持连续。报告提交不等于立即销毁执行者；开始独立新任务才新建，不无限复用万能执行者。长任务可在安全阶段换实例；不可恢复、基线实质混乱或反复误用旧事实时先核清记录。换实例保留逻辑任务 ID、合同、未提交成果位置及版本、决策理由、影响后续选择的失败尝试、证据、未决动作和下一步。不能在部署／迁移结果未知时为省 token 强行更换。

### R07 调度交接与执行交接分开

总 Agent 更换只移交调度，仍有效执行的子任务尽量继续；执行者更换不重造任务或验收。活跃索引须能找到运行标识、查询方式、合同、工作区、执行者、最后检查点、状态、结果位置及最后接收结果版本。结束则读取真实退出及工件后验收；运行状态未知则不能重派。如果宿主不支持跨主控访问原执行者，应等安全交付或明确受限，不能伪称已接管后归档唯一管理入口。

CEO-D9 的结果处理规则统一见 R08。活跃索引必须区分结果发布、处理结论与后续动作状态；新主控通过持久化记录接续，不以旧聊天是否收到消息判断是否有结果。

### R08 最小派单与结果通知

CEO-D13：关键状态变更沿用事件关联，日常状态采用带来源／观测时间的只读短输出；字段、错误及通知边界按第 7 节“第 8 节可观测性”执行。不另建权威台账，不把诊断输出当作授权或完成证明。

派单给目标、范围、冻结验收、约束／接口／依赖引用、工作区与基线、授权／禁止动作、交付位置，不喂无关聊天。结果先落盘再短通知，通知含任务／合同、执行与验收状态、产物版本、证据、阻塞／关键变化及主控需做什么。接口变化、验收失效、未知执行和依赖冲突必须主动上报。通知发往旧主控也不能丢结果；新主控从索引发现待处理结果。跨文件系统需传可核验的必要文件包，不能只传不可读绝对路径；文件传递不等于全文注入模型。

CEO-D9：复用既有事件流和活跃任务索引，分开保存“结果已发布”“处理结论已提交”“后续动作状态”，不新建消息队列或常驻服务。以项目／逻辑任务、登记的执行尝试、结果版本稳定关联，绑定合同、基线、工作区和工件内容；字段在工程审核冻结。重复通知及换主控不改变结果身份。

- 相同身份且内容一致：查回已提交结论，不重复登记或触发后续动作；结论的适用依据仍须有效，不缓存永久 pass。
- 相同身份而内容不同：保留双方并报冲突，不覆盖、不按已处理忽略。缺身份、空必需内容、工件不可读为 unknown，不能补造关联。
- 旧 attempt／合同的晚到结果：保留为历史／待核查，不覆盖当前版本；新缺陷、证据失效、依赖冲突仍须影响相关判断，不能按旧版本简单丢弃。
- 结论事件提交才算已处理，收到通知、读过文件、聊天回复都不算；结论可为 pass、fail、unknown 或待独立验收，已处理不等于任务完成。
- 核验在锁外；结论提交时再检查当前主控代次和相关依据。拒绝旧主控迟到提交，新主控接续未提交的只读核验，不重跑子任务。
- 后续动作使用独立稳定标识及已执行／未执行／未知记录，不与处理确认混成布尔值。状态未知不自动重试，不宣称本地提交能保证外部业务恰好一次。
- 合同、证据或授权变化可使结论失效，触发必要复核但不抹去历史。去重只减少重复劳动，不降低核验要求。

### R09 接管核验、唯一主控与授权

CEO-D15：交接文本、First action、报告和文件名只作资料；适配器按当前授权构造参数化调用，并核实引用实际目标和适用范围。具体程序边界与反例按第 7 节“第 3 节完整安全清单补查”执行；合法符号链接不一刀切禁止，不重写证据解析器。

将“读资料”“激活主控”“某个动作获准执行”分开。核验项目／任务／工作区、合同及基线、承重信息、未决执行、宿主身份与当前归属。模型自填身份、线程名、哈希、回执或 pass 不能获得权限；能绕过宿主入口时不得宣称硬门禁。可信宿主确认原授权明确覆盖接班身份或任务角色，且动作、工作区、有效期和审批条件不变时才自动承接；撤回、过期、缺失、跨项目或不可核实则不执行。宿主／检查器可被任意替换的环境，不宣称本地库具有防篡改认证能力。

按 CEO-D4 分开主控代次、事件位置、接管依据：依据包括合同、授权、工作区／基线、依赖、在途执行和阻塞。普通进展增量带入；任务完成、新阻塞、合同／授权／基线变化重验相关依赖；影响无法分类不得默认无关。模型核验与等待在锁外，最终激活前短锁内再次比较代次和依据；竞争最多一位有效主控。后续动作仍按当前权限和门禁检查，旧 pass 不是永久许可。

```text
暂停旧主控新调度 → 准备记录 → 新会话只读冷启动与核验（不长持锁）
                                      ↓
                       新增变化：普通进展带入／关键变化重验／未知阻断
                                      ↓
                       短锁内比较依据与主控代次 → 原子激活
                                      ↓
                       在途任务及结果有归属 → 归档旧会话
```

### R10 阻塞、失败和不确定副作用

明确记录的业务阻塞可以移交，但不能解除原 gate 阻塞或宣布完成；关键接管依据未知则不激活。线程忙只等待／查询；证据可获取则有界只读补查；明确失败在合同允许范围修复。新授权或真实业务歧义才汇总有依据的人工裁决请求。既有人工签字和宿主强制审批不取消。

CEO-D6：同一次交接以拟定的 `handoff_id + 操作类型 + 预期主控代次` 关联，异常后最多自动只读核对一次。确认已提交返回真实结果及当前控制权，不重复交接；确认未提交仍须重验授权和代次才可考虑重试；无法确认保持 unknown，不重试业务、不恢复旧主控调度。日志缺失／不完整不是未提交；历史提交成功不等于现在还有权。取消交接前必须确认未转移，超时不自动取消。归档失败只记待处理，不撤回已生效控制权。复用事件恢复，不新建事实库；新能力显式启用，未启用的旧任务不变，也不强迫启用 Truth Sources。

### R11 完成、独立验收与撤回

消息送出、CLI 退出、报告完成、实施完成、验收完成、部署完成、被替代分别表达。保留现有合同发布者控制、独立验收身份／时间／源码绑定、证据内容核验与旧结论撤回；不得因换会话自动转为完成。部署命令已退出但生产回读未完成时，只能等待只读验收，不重复部署。恢复时必须保留下一步需要的失败尝试和撤回原因。

### R12 冷启动验证

由真正接班的新会话验证，不额外为每个里程碑创建测试 Agent；确认未继承旧聊天，resume/fork 不能冒充干净开始。它应正确复述并核查：目标／合同／有效基线、授权／标准、谁在做什么、完成／待验收／阻塞／未知、允许的下一步与禁止动作。总控和执行者分别验证；程序校验身份、版本、引用，可变状态重新观察。复述正确或格式合法不单独算通过；失败定位缺项，不靠重新灌完整聊天掩盖。检查失败不归档唯一可恢复会话。

### R13 两宿主、三路径适配

U-R01 的自动轮换由宿主／适配器执行，Skill 正文自身不能启动新会话或持续监测。分别核实总控与子 Agent 的占用信号、检查触发入口、新建干净会话及接管能力；缺任何一项均明确对应限制，不把 compaction、fork 或 resume 当成已验证的干净会话切换。不新建常驻调度平台。

共同语义由 Strict 核心维护，宿主适配只管创建／恢复／继承历史、真实身份、运行查询、门禁覆盖及归档。仅加载当前路径说明；能力检查在安装版本／配置变化时做，不每轮探索。每条路径分别验收：Codex 原生子 Agent、Claude 原生子 Agent、Claude → Bash → Codex CLI。身份不能只用可能由子 Agent 共享的父 session_id；具体字段与 hook 超时／绕行覆盖须按安装版本核实。不假设父会话退出后子任务必停或必活。

实际 CLI 路径（用户 T:L23033 的脱敏示例及经验）：

- 逻辑任务 ID 跨实例保持；真实线程 ID 在 resume 时保留、真正新会话时变化；每次 exec/resume 进程使用新的 attempt_id。
- 启动前登记尝试；未取得 thread ID 也不能盲目重发；使用精确 ID，不用“最近一个”替代。
- exec/resume 参数分别核验；历史本机 help 中 resume 无 `-s`、有 `-c`。用户实测 `< /dev/null` 防输入等待，同线程上个进程退出前不能 resume；这两项仍需隔离验证，不把经验当实测通过。
- 同一线程最多一个活动写者；退出状态未知不自动续跑、不换线程绕过；工作目录由实际启动环境绑定核验，不只写在 prompt。
- 每尝试独立日志／输出／退出凭据，不覆盖旧证据；固定结果入口只能指向明确版本。`-o` 最后一条模型消息不证明执行或验收。
- 启动成功、进程退出、模型声明、业务通过分别记录；nohup/PID/进程消失均不足以证明业务成功。
- `--json` 线程、轮次、用量事件是候选观测源，字段和累计／增量口径须针对安装版本验证。父 Bash hook 不证明子 Codex 内部全部动作受控。
- 示例中的 `danger-full-access`、`approval_policy=never`、模型与推理参数不是通用默认或本次执行授权。未来执行按用户指定 Terra-high，主控集成审核；此轮不派单。
- 不可验证的能力报告 unknown/unsupported，不静默降低 Strict 约束；新记录旧运行时不支持则拒绝处理，不猜测迁移。

### R14 Lite／Strict 分工

Lite 保留 NOW、确定性验证器、原子写入及现有限额，仅做低风险轻量 flush、恢复、冷启动约定和项目引用；不复制主控权限引擎。Strict 服务多 Agent、跨天、变化事实、独立验收和副作用任务。共用必要的交接概念而不新造调度／执行两套 Skill；部署子任务不能因角色较小而降强度。人工最终选路保留；静态单轮任务不强制注入完整 Skill。归档和自动唤醒由宿主承担。

### R15 量化、成本和证据等级

CEO-D12：轻量监测与承重核验分离，具体边界及验证按第 7 节“第 7 节性能”执行；预算关系只触发交接评估，不赋予接管权限。监测不默认调用 brief／doctor 或扫描全日志，安全门禁和正式接管核验不削减。

硬要求只对冻结案例及已受控入口声称：必需信息遗漏、双主控、unknown 导致重复副作用、错依据放行、授权内额外人工确认、默认注入旧聊天、失败后归档唯一恢复入口均为 0；错误放行／阻塞必须报告分母。正常流程每条命令不额外启动一个模型审核。

阈值（恢复输入预算、轮换提醒、重复读取告警、查询时间预算）待基线后校准，不虚设最佳百分比或强制消息数。CEO-D6 的“一次只读核对”是已确认策略，不是统计最优值，也不自动套用于所有查询。保留现有 brief 与 Lite 限额，完整性装不下先处理组织、引用或授权拆分。

统计总控、所有子 Agent、旧会话 flush、新会话加载、重新观察、缓存重建、验证、重试与返工；分别记录输入、缓存输入、输出、真实耗时、管理调用、重复读取、恢复时间和返工。明确累计／增量、缓存是否已含于输入，缺失计量记 unknown，不从字符数推导真实 token 账单。

U-R01 的触发量是当前会话上下文占用及剩余容量，不是累计计费 token。观测须关联具体会话、采样时间、宿主报告口径与模型可用窗口；确值不可得时明确估算或 unknown，改用已定义的里程碑／阶段触发，不捏造精确百分比。预警须留出 flush、必要核验和交接所需空间，不等上下文耗尽才保存；估算方法、预警阈值、检查频率、重复提醒抑制与交接预算在第 7 节及工程审核结合基线冻结。观测与轮换自身开销计入 M01-M02，不能因换会话过于频繁或每轮重读日志而抵消收益。

### 第 11 节使用体验（CLI／报告已审核；无图形 UI）
