## 本轮任务与验收（2026-09-10，执行前确定）

目标：用实际任务判断有效性和使用负担，不预设 token 收益。
范围：仅新增本台账与 `real-project-observation.template.md`；复用现有报告作历史线索。
禁止：修改 Skill、安全策略、其他项目；提交、安装、推送、生产操作、收费模型调用。
交付：观察流程、轻量模板、明确区分历史线索与新样本的台账。

验收：

1. 模板分别记录包身份、加载证据、执行证据；已安装不得替代实际执行。
2. 同一模板容纳正确放行、正确阻断、漏拦、误拦、未触发和 unknown；有原始证据及复核位置。
3. 用量缺失为 unknown；记录任务整体成本及测量边界，不从字符数或不同项目直接推导节省比例。
4. 历史材料明确标注未重新核验，不计作当前版本自然验证；新样本为空时明确写零。
5. 两份新增文件做内容检查和 whitespace 检查；不以文档检查替代 Skill 行为验证。

## 最小操作流程

- 用户提供 2–3 个当前使用项目或任务记录路径后，只读定位实际使用的完整包、会话加载与工具执行记录。
- 每个选定任务登记一次，结束时补一次；中途只记恢复、交接、过期事实、冲突、完成判定等关键事件，不逐轮记账。
- 连续登记选定范围内的任务，包括正常完成、未触发、失败、中断和记录不可得，避免只挑成功案例。
- 先根据任务当时的要求与原件写预期行为，再核对 Agent 判断和工具结果；历史回顾标注 retrospective，不能冒称判据预先冻结。
- 由主控定向读取原件复核。路径、哈希、模型自评或工具返回 pass，单独都不是语义正确的证明。
- 发现漏拦或误拦，保留双方证据；在脱敏、隔离的最小复现中调查，不在生产环境关门禁或重放业务动作。
- 首批 3 个可复核的完整任务后做一次描述性汇总；这是整理节点，不是统计充分性标准。严重漏拦发现即报告。

## 判断与成本口径

先判断有效，再判断经济；不得把漏检查、漏记录或未完成算成节省。
预期继续且实际继续为正确放行；预期阻断且实际阻断为正确阻断。
预期阻断却继续为漏拦；证据足够且应继续却被阻断为误拦。
规则不适用记未触发；判据、轨迹或原件不足记 unknown，不强行分对错。
分别保留 Agent 原始判断、checker 结果、实际动作和最终任务结果。

汇总报告总登记数、可复核数、未触发数、unknown 数及各结果计数；小样本不外推失真率或稳定性。
从现有 usage 提取 input/output/cache 用量、重试、额外回合及耗时；明确单位和起止范围。
只拿到单轮 usage 时不能写成全任务总量；无法归因于 Skill 的成本不能全部算作 Skill 开销。
不为采集而额外调用模型；没有 usage 就记 unknown，不填 0。
自然观察不能证明因果性 token 收益。后续对照需固定任务、完整包、模型/推理设置和评分规则，并另定调用预算。
