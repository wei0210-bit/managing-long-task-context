# E1-03 验证前置草稿（不派发、不授权越过 #17）

状态：#17 未验收，#18 仍阻塞。本文件只记录后续验收必须分清的时序与证据；实际接口/所有权/命令在派发合同中再冻结，不作为当前实现任务。

## 避免重做与误判

- 使用同一权威事件流、锁及三个既定事件，不新增平行提交数据库；不得只检查 snapshot。
- `check_status` 是当前依据有效性，`commit_status` 是既有提交事实。已刷盘激活后即使证据后来过期，不能把激活事实改成未提交；应明确当前检查 unknown/fail 与已提交事实并存。不根据证据缺失去复活旧主控。
- 相同请求重试只读回原提交事实，不再次提升代次；同 ID 不同操作/内容必须冲突。不能让“当前 expected generation 不匹配”掩盖同请求已经成功的事实。
- 长任务不只交接一次：第二次交接、上次已取消后新交接、历史多个已结束 handoff 与当前唯一 pending 必须可区分。#17 当前实现只接受首次 prepare/同请求幂等，不能把此阶段限制误发布为最终能力；#18 需根据完整控制状态投影审核收口。
- 普通事件序号不是主控代次。合法在途子任务继续报告不等于自动修改控制权；新主控承接既有子任务许可不得扩大范围。
- 激活必须在该次调用实查候选身份、原范围承接许可、合同/包/工作区、承重依据；不能直接接收上次 `validate_handoff=pass` 字典。

## 派发前应冻结的可观察时序

1. 正常激活：一条 activated 事件，generation +1，只有目标主控可控制写入，旧主控迟到写拒绝。
2. 同时竞争：使用进程/线程屏障安排两个候选，同一权威任务最多一条激活事实；没有以“发了两次消息”代替进程竞争。
3. 核验后承重依据改变：提交前再核实，拒绝旧核验结果；没有业务副作用。
4. 普通子任务进展穿过核验期：依赖未改变时不误当双主控；可核查的范围内子任务结果可继续登记。
5. fsync 之前中断：按可读权威事实确定未提交，部分/不完整尾行保持 unknown；不自动重试业务。
6. 已 fsync 事件、snapshot 更新失败：新进程只读状态确认已提交、代次 +1，不补写第二条事件。
7. 已提交但响应丢失或写进程被真实终止：新进程 status 确认；声明是进程故障，不声称机器掉电持久性测试。
8. 不可读/损坏权威日志：unknown、零写入，不仅凭旧 snapshot 判断未提交。
9. 同请求重放、异内容冲突、激活后取消、旧窗口重启：分别验证提交数、代次、身份边界；不靠超时恢复权限。

## 证据要求

每种时序保留父子进程退出码、屏障阶段、实际 events/record 摘要与 hash、代次和文件写入对照。一次进程至少返回可复核的 stdout/stderr，不把进程启动当完成。真实 OS 临时目录和真实文件 I/O；宿主身份明确 synthetic。注入真实文件系统边界/子进程信号，不 mock 自有提交方法直接返回成功。

E0 输入 pin、#16/#17 测试、主控独立 probes 及旧 gate 回归继续适用；E2 分发副本未同步不得删掉旧失败断言。真实模型/自然项目/token 收益另计，当前均未测。
